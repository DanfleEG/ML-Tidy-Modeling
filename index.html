What Is a Model?

A model is a mathematical representation that captures the essential structure of a complex phenomenon.


General Form
$$Y = f(X_1, X_2, \ldots, X_p) + \varepsilon$$
Linear Specification
$$\hat{Y} = \beta_0 + \sum_{j=1}^{p} \beta_j X_j$$

🔍 Reductive capacity
Simplify complex reality into tractable structure

⚖️ Bias–Variance trade-off
All models are wrong; some are useful — Box (1976)

Y → outcome X → predictors ε → noise

Taxonomy of Models

Three primary objectives drive every modeling effort.

Descriptive Models

Goal: understand what is there, not why.


Trend Detection
Summarise central tendency and direction over time or across groups.
LOESS Smoothing
Locally-weighted regression reveals non-linear patterns without parametric assumptions.
Pattern Exploration
EDA-driven — the model serves the analyst's curiosity, not an external standard.

Non-parametric trend without distributional assumptions

Inferential Models

Goal: draw conclusions about a population from a sample.


Concept Description
Hypothesis H₀ vs Hₐ — formal claim about a parameter
p-value P(data | H₀) — probability under the null
CI Range of plausible parameter values
Assumptions Normality, independence, homoscedasticity

Null distribution with rejection region and confidence interval

Predictive Models

Goal: maximise accuracy on new, unseen data — not just explain existing observations.

Mechanistic
Grounded in domain theory.

• Parameters have physical meaning
• Extrapolates more safely
• Requires strong assumptions

Example: pharmacokinetic dose-response
ODE-based Theory-driven
Empirical / ML
Learned from data patterns alone.

• Parameters are latent / opaque
• Excels at interpolation
• Requires large samples

Example: gradient boosted trees
Data-driven High fidelity

Both types share a common imperative: generalisation — performance on data the model has never seen.

Iterative Modeling

Modeling is never linear. It is a cycle driven by feedback at every stage.


EDA
Distributions, correlations, outliers — what does the data tell us before we ask?
Feature Engineering
Transformations, interactions, and encodings that inject domain knowledge.
Tuning
Hyperparameter search over a resampling scheme — never on the test set.
Evaluation
Honest performance on a held-out set after all decisions are finalised.

Case Study: Chicago Transit Authority

Predicting daily rail ridership — an analyst's internal monologue.

📊
Step 1 · Correlations
Which stations co-vary? Is ridership autocorrelated? Weekly and monthly seasonality emerges.
🌡️
Step 2 · Weather
Temperature and precipitation enter as features. Cold/rainy days suppress ridership non-linearly.
📅
Step 3 · Holidays
Federal and local holidays create sharp dips. Engineered as binary indicator variables.
🌲
Step 4 · Boosted Trees
XGBoost captures non-linear interactions between weather, calendar, and station-level effects.

The analyst never fits a model first — every feature is motivated by domain reasoning before statistical evidence.

Conclusions

🔄 Modeling is iterative
EDA, feature engineering, tuning, and evaluation form a cycle — not a sequence.

🧰 Software shapes practice
Good tools enforce reproducibility, protect against leakage, and make correct practice the default.

🤝 ML and statistics are complementary
Machine learning provides predictive fidelity; statistics provides inferential rigour. Both are needed.
